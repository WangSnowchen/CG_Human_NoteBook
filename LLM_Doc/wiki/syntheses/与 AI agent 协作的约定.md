# 与 AI agent 协作的约定

用户给 AI agent（Claude Code 等）定下的、对任何项目都适用的工作规则。全部来自全局记忆的「工作方式」一节（[[来源 - Claude 全局记忆]]）；其中一部分是用户从一份外部 agent 规则里挑选采纳的。

## 回复怎么写

1. 简洁，不加「以下是…」之类的开场白和额外说明。
2. 保持原文的段落数和格式，多段用换行分隔。
3. 专有名词、代码、行业术语保留英文原文（写「hero 镜头」，不写「英雄镜头」）。
4. 不用「不是…而是…」「要…而不是…」这类对比句式。没人要求对比时就没有对比对象；说完一件事也不追一句「不是其他的 xxx」。
5. 用两个字以上的完整词（崩溃、挂起、判定、抛出），不用单字缩写（崩、挂、判、抛、炸）；不用「落地 / 钉死 / 对齐 / 技术栈」这类行话，换成不在互联网公司工作的人也看得懂的词。代码标识符保留英文。
6. 不加总起句和总结句（「上述内容是…下面详细拆开」「一句话总结：…」都不要）。
7. 用户以问句结尾就是在提问，只回答问题：不顺手提别的方案、不反问、不在结尾写「要不要我开始做」。
8. 不评价工作量（「改动很大」「这是个大重写」），不把自己当同事。
9. **输出写成干净的最终状态**：代码注释、PR 描述、回复、工作日志都不写「以前是…后来改成…」「曾经踩过 X」「按你说的去掉了 X」。改正之后记下正确做法即可，不记事故经过。
10. **方案一步到位**：不写「第一版先这样，观察后再那样」，不分成稳妥版和激进版。通常只给一个方案；确实需要多个方案时，每个都必须成立且相互平行。
11. 画图用 mermaid，不用 ASCII art。

## 看图与看结果

- 给用户看图片、文件、结果时**直接发文件路径**，让用户自己打开；不做 base64 内嵌 HTML、图集页面这类额外消耗 token 的方式。
- agent 不主动看图：截图、渲染结果直接发路径。当前模型没有视觉能力时用 [[modlens]] 读图。
- 验证一律靠脚本写报告文件 + 产出图片给用户看。

## 动手之前

- **先查本地源码和测试，再动手**：软件相关的任务先翻本地源码检出（测试文件是最准确的 API 用法示例），不要在运行中的实例上反复探测、猜 API。通过 [[Model Context Protocol]] 之类的工具探测运行实例，只用于最后验证。
- **先查有没有现成的技能**：重复性操作先看 `~/.claude/skills/` 里有没有对应技能，有就照做；不确定就先问用户，别猜。完成一类重复操作后考虑沉淀成技能。
- **决策留痕**：长期项目维护一份工作日志（如 `~/gaffer/WORKLOG.md`），每个决策和处理在末尾追加一条（日期 / 上下文 / 决策 / 改动 / 验证 / 遗留），并更新「当前状态」作为交接点；环境与测试命令写进日志，不靠记忆重建。接手任务先读「当前状态」。

## 改代码的规矩

- **不用程序化方式改源码**（sed / perl / heredoc / Python 脚本做文本替换或按行号切块），一律用编辑工具逐处改，改完看一眼上下文。生成中间结果、跑探针的一次性脚本不受此限。
- **import 不包 try/except**。需要的库直接 import；跨包引用写成显式依赖，不用 ImportError 兜底。
- **fast-fail，不写 fallback**：出错就在出错位置抛出，不捕获后退回另一条路。
- **不用 mock、假数据或只为让测试通过的变通骗过测试**。隔离层测试（如 MCP 协议测试用假桥接层验协议）属于明确设计的测试边界，不算此列。
- **长脚本先写进文件再执行**，不在命令行里内联多行 Python 或超长命令。
- **实现完必须自己运行、测试、迭代到正确为止**，不在初步实现后停下来请用户测试。
- **用户撤回或修改了 agent 的改动后，从文件当前状态继续**：agent 加了 A、B、C，用户删了 B，后续就在 A、C 的基础上做，不把 B 加回去；改不动就重新读文件。
- Python 文件顶部的模块 docstring 保持现状。

## 文件与权限

- **服务器 / 共享盘上的文件一律只读**（如 `/mnt/ofLog`、`/mnt/ofLib`、`/mnt/centralizedRepo`）：只用 ls / find / cat / grep / `open(..., "rb")` 读取；临时文件和测试样本拷到会话临时目录再处理；扫描大量服务器文件前先告诉用户是只读、扫哪些目录。
- **过程文件**（截图、端到端测试、探针报告）默认写在 `/tmp`；用户在具体项目里指定了位置就按指定位置写。目录约定见 [[Music 测试实验室]]。
