# 相机分辨率门外的物体仍在绘制

## 现象

Gaffer 视口里透过场景相机看时，分辨率门外那一圈的物体照常绘制，门外用不上的部分照样消耗帧时间（[[来源 - Claude 全局记忆]]）。

## 原因

Gaffer 透过相机看时，给 viewport 装的相机能看到整个门再加 40 像素边距，门只是画在上面的叠加层。视锥按 viewport 相机计算，门外那一圈都在视锥里。

## 解决

[[gaffer_indexed_mesh]] 分两层处理：

1. **按门剔除**：`BatchFlushGadget` 记住所在的 `SceneView`（`installBatchFlush( viewport, view )`，钩子只对 SceneView 安装，关掉合批时也安装）。Back 层取 `view->resolutionGate()`（raster 坐标，左上原点）换成 NDC 存进 `BatchQueue`；`Cull.h` 的 `boundVisibility` 把四个侧面从 x = ±w 换成 x = gate·w（都是过原点的平面，齐次判定不受 w 符号影响）。网格和原生占位框都用这个判定。`GAFFER_INDEXED_MESH_GATE_CULL=0` 关闭。
2. **scissor**：包围盒剔除只能整块丢，横跨门线的地面块、点云块门外那一半还会画。`GateScissorGadget`（类型 id 799007）排在 SceneGadget（viewport 的子节点 `__primary`）正前面，在 Main 层打开 `GL_SCISSOR_TEST`、范围设为门的像素矩形；`BatchFlushGadget` 排在 SceneGadget 正后面，flush 完恢复。`installBatchFlush` 用 `reorderChildren` 把顺序排成 `[scissor, __primary, flush, …]`。

scissor 只能在 Main 层打开：[[ViewportGadget]] 每一层都要清中间 FBO、blit、合成，这些操作都受 scissor 影响，在 Back / MidBack 层打开会把它们一起截掉。门线和相机名的叠加层在 MidFront 层，不受影响。

剔除的整体做法见 [[视锥剔除]]。

## 验证方法

用一块横跨门线的大地面加一个球阵列：门外的场景像素 43540 → 0。

测试时注意：

- 门正好等于相机 FOV 时，阵列铺满门，没有一个球在门外，看起来像没生效。
- 数「球」的像素只认 r = g = b 的：门角的红色裁剪标记、坐标轴也不是背景色。
- `apertureOffset` 验证不了 y 方向：Gaffer 会把视口相机连门一起挪，门永远居中。
- [[Gaffer screengrab]] 默认展开深度是 0，要设 `view["minimumExpansionDepth"]`。
- `imath.Box2f.min()` 是方法，要带括号。
