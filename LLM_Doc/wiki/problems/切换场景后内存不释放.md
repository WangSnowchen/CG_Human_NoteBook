# 切换场景后内存不释放

## 现象

在 Gaffer 里展开一个大场景，然后关掉它的窗口或切到另一个场景，进程 RSS 和显存都不下降（[[来源 - Claude 全局记忆]]）。

## 原因

三个持有者：

1. **Gaffer 计算缓存**：Gaffer 1.7.1.0 日常启动下上限 48 GB，按插口哈希存、不区分脚本，关掉窗口也不清。
2. **[[gaffer_indexed_mesh]] 的 arena 空块从不回收**：网格删掉后留下的空块，显存和驱动在主存里给它留的拷贝一直占着（arena 见 [[Multi Draw Indirect 批量绘制]]）。
3. **mmap 的 usdc 文件**留在 page cache 里。这部分系统需要时会回收，不算泄漏。

## 解决

1. 本地扩展 `gaffer_default_values` 里 `registerCacheRelease( application )`：关脚本时调用 `Gaffer.ValuePlug.clearCache()` 和 `Gaffer.ValuePlug.clearHashCache()`。
2. `Arena::collect( context )`：每帧开头和分配新块前回收空块。缓冲在多个 GL 上下文之间共享，随便哪个上下文都能删；VAO 不共享，只能由创建它的上下文删。

`SharedSceneInterfaces.clear()` 和 `malloc_trim` 试过，没有收益。

结果：两个窗口各开一个场景，关掉 A 之后 RSS 30.4 → 9.1 GB。

## 验证方法

- `tests/screengrab_scene_switch.py` + `run_scene_switch.sh`：两个窗口分别展开、收起、关闭，每一步逐项释放，看各项各降了多少。
- 内存要拆开看 RssAnon / RssFile / 计算缓存 / 显存，拆法见 [[Gaffer 视口展开大场景内存暴涨]]。
- 量显存或 arena 用量前把视口 `clippingPlanes` 设成 (0.1, 1e7)，默认远裁剪面会让大半场景不上传。
